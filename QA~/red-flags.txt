# This copy ships in the SDK package QA~/ and is version-pinned with the SDK: it is
# the canonical red-flag list for this SDK version.

# SDK/vendor red-flag substrings — these MUST NOT appear in a QA run, and any
# hit is BINDING (it halts the run). Scope: SDK and vendor init/delivery failures only.
# A game's own exceptions and content errors are NOT here: they are informational, they
# live in game-exceptions.txt, and they never fail an SDK-scoped run (a game with its own
# NullReferenceExceptions can still have a completely healthy SDK integration).
# One substring per line. Lines starting with # are ignored.
# Grep list applied to a RAW capture (iOS devicectl console log or Android logcat).
# Usage:  grep -Ff <(grep -v '^#' red-flags.txt | grep -v '^$') <capture>
# (strip comments/blanks first: grep -Ff treats every line, including these comments,
#  as a pattern; raw -Ff has false-fired on innocuous comment lines before)
#
# These are UNIVERSAL (apply to both interim QA and release validation). Context-sensitive
# reds (e.g. "Sandbox" is OK mid-development but fails a release build) live in the
# release-gate definitions, not here.

# SDK mode leaks
# Prototype mode is valid for a prototype-mode game.
# Full-mode and release-only checks live in the release-gate definitions.

# Facebook app access token rejected (cred mismatch) or app invalid/deleted.
# Real Android log shape is "errorCode: 190" (colon) inside the GraphResponse JSON.
# The old "errorCode 190" (space) pattern NEVER matched a real capture and let a
# broken FB init pass QA on two games (2026-06-10). Match the JSON shape and the
# human-readable forms, not a remembered shape.
# iOS GraphResponse delimiter unverified: confirm against an iOS capture.
errorCode: 190
OAuthException
Invalid OAuth access token signature
Application has been deleted

# ATT attribution cliff — zeroed IDFA reached Adjust
idfa 00000000-0000-0000-0000-000000000000

# ATT-gating regression (v3.16.0): "ad_personalization=Granted while ATT denied" is a
# CORRELATION across two log lines, NOT a single forbidden substring, so it is NOT listed
# here — a bare grep for ad_personalization=Granted false-fires on every healthy ATT-allow
# run. That correlation check lives in the release-gate definitions, not this file. Verify:
# any non-authorized ATT (att:2/att:1/att:0) MUST coincide with ad_personalization=Denied.

# Firebase Core init failure — events silently dropped (appear in Vitals, never reach Firebase)
Firebase init failed — dropping analytics events

# Game-owned patterns (FATAL EXCEPTION, NullReferenceException, InvalidKeyException) moved to

# The bare `<private>` pattern was deleted in the same pass: on a device-wide iOS capture it is
# ordinary OS redaction, hundreds of thousands of hits, and it never described SDK state.
